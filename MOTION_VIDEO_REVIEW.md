## Use
Run `python3 proxy.py 8730` from this extracted folder; open `http://localhost:8730/#/skills`. This is a local review command, not deployment authorization. Existing Settings owns the API key. Planning is a paid text operation only when the user explicitly clicks Plan; reviewing prices is public. The old Motion Trimmer remains planning-only and its existing request is unchanged.

The new card opens one modal: brief/context/platform → 5/10/15-second plan → editable JSON shot beats/overlays/dropped details and separate editable prompt → Refresh exact price → explicit Generate approval → queued/processing → inline Blob player/Download MP4. There is no automatic video fallback, regeneration, composition, stitching, music or uploaded assets. Overlays are editor instructions, not burned into the MP4. Exact typography, brand assets, easing and second-perfect edits are not promised. Review generated prompts before any future approved render.

Video choices are only `alibaba/wan-3.0/text-to-video` at 720p (default, 15 seconds) and `minimax/h3-max-turbo` at 768p. Exact public-config prices are refreshed for review and checked again before POST. Unknown config/pricing blocks. Planner uses one structured `anthropic/claude-sonnet-5.5` call, with `deepseek/deepseek-v4.1-flash-1017` only after a 5xx; invalid JSON and auth/credit/rate/network failures do not trigger a fallback. Each attempt has a $0.10 heuristic preflight, not a billing cap. Planner estimated usage receipts and video quoted/pending/settled receipts are separate; missing cost never means zero.

## Recovery and privacy
Only minimal job references, quoted configuration/cost, opaque idempotency token, request hash and creating-key hash are retained in `motion-video.v1`. No prompt, API key, Authorization header or result URL is persisted there. The opaque idempotency token is not the API credential. Up to 20 references are retained; full/unreadable recovery storage fails closed. Do not clear browser recovery data while a creation may be outstanding.

Double clicks and separate tabs are serialized with an exclusive origin-wide Web Lock, with recovery storage re-read under that lock before submission/new-version decisions and merged under the same lock on updates. Missing safe lock support fails closed (including insecure non-local HTTP contexts). Open views refresh shared references on storage events. A new logical version persists one shared plan/version identity; its Idempotency-Key is SHA-256 of canonical `{planId,model,prompt,duration,resolution}`, not a per-tab random request token or a global prompt-only key. An intentional repeat after terminal completion gets a new identity/token even with the same prompt. All retained same-account pending/uncertain records guard new generation, regardless of history selection; the UI also disables new generation while retained pending work exists. A lost create response is uncertain, not free or cancelled. Retry is explicit and uses the same token and byte-identical body. After reload, re-enter the identical prompt/configuration to retry an uncertain creation; an edited body is refused, not sent under a fresh token. A known job resumes with GET only and the creating key. No automatic POST is made on reload. Auth/credit/not-found/network failures remain distinct from failed generation and failed content download. A definite create-time 401/402 is a rejected submission with no created job; it can be replaced explicitly after fixing Settings/credits. Network/5xx/ambiguous responses remain uncertain and must not be treated as uncharged. A completed job whose download fails is still charged; Retry download only never generates another job. Terminal versions stay in the job-reference selector for later authenticated re-download.

Polling uses bounded backoff and a 3-minute local deadline, with bounded requests. Explicit Resume starts a new local observation interval. Closing/pagehide stops polling, not the upstream job; no cancellation/refund promise. Changing the key requires closing/reopening the flow; a key hash prevents accidentally resuming with a different key. Recovery depends on retaining the exact creating key in existing Settings. JSON edits are validated for numeric duration totals and typed in-range overlays; this does not prove creative truth or semantic model compliance.

Content always uses `/v1/videos/{validated-id}/content`, authenticated fetch, and a memory-only Blob URL. Absolute gateway content URLs may validate to that exact path, but arbitrary hosts, paths, queries, fragments and redirects are rejected and never followed. Keys are never inserted into media URLs. Blob URLs are revoked on replacement/close. The proxy forwards Idempotency-Key only on POST `/v1/videos`, streams bounded chunks with a 100 MiB maximum, and does not follow media redirects. Known oversized content returns 413. Unknown-length media uses HTTP/1.1 chunked completion framing: overflow or upstream failure closes without a terminating chunk, so a prefix cannot be accepted as a completed download. The client checks byte count against Content-Length when present and the same 100 MiB bound; failed/incomplete transfers create no Blob and show exactly `Download incomplete, retry download`, with only download retry offered until successful. Video HTTP error bodies are closed without reading (zero upstream error-body bytes, below the 64 KiB cap), and only a small fixed safe `error_message` is returned; upstream diagnostics/headers are not reflected.

## Review and operational handoff
No live server has been replaced. Before any later authorized deployment, back up the current runtime and exact start configuration. Extract into a new reviewed directory, compare the supplied SHA256, run the local smoke/security checks, then restart the exact owning proxy process using the owner's existing process manager. Do not launch a second listener on an occupied port. Verify root 200, legacy flows and GET/HEAD source-denial 404 after restart; rollback by restoring the prior runtime and restarting that exact service. A public source branch or ZIP is not a deployment.

The ZIP contains runtime files and this README only: no private design, test Python, reports, API credentials, pricing snapshots, caches or build artifacts. `proxy.py` is required runtime Python, not private test source.
