## History, recovery and privacy
Only minimal job references, quoted configuration/cost, opaque request identity/hash and key hash are retained in `motion-video.v1`. No prompt, API key, Authorization header or result URL is saved there. Twenty references is the maximum for starting another job. **Clear finished jobs** removes only the active account's completed/failed/rejected references; all unresolved states and every other account's references (including finished downloads) remain. Unattributed legacy references are preserved. The operation re-reads and filters under the same origin-wide exclusive Web Lock, preserving concurrent pending work and selecting a remaining job when the selected finished job is removed. It does not cancel jobs or imply a refund. Do not manually delete unresolved browser recovery data.

Double clicks and tabs share locked read/merge operations. A version identity is persisted before POST, and its request-derived Idempotency-Key is retained for identical retries. No safe lock means no generation. Pending same-account work blocks a new request irrespective of selected history; the UI also disables new generation while any pending reference exists. “Make another version” is available only after resolved work and uses a new identity. A lost response does not imply a free or cancelled job: re-enter identical prompt/settings and retry the same saved request. Reload never submits automatically. Resume uses GET with the key used to start the video. Definite create-time 401/402 rejection is distinct from an unconfirmed start. Auth/credit/not-found/network errors are surfaced; errors stop observation and require explicit Resume rather than busy retries.

While the panel is open, status polling has **no overall three-minute deadline**. Backoff grows from one second to at most 15 seconds. Each status request still has a 20-second abort timeout; other JSON requests have a 30-second timeout. Closing/pagehide aborts polling and its timer, not the upstream job. Closing during create does not start polling later. Terminal status and settled receipts are merged monotonically under the lock, so delayed processing cannot replace a completed/failed result. A completed video with a failed download remains charged; Retry download only does not create a second job.

## Content and legacy guarantees
Content uses authenticated `/v1/videos/{validated-id}/content` fetch and a memory-only Blob URL, revoked on close/replacement. No API credential is put in media URLs. Redirects, other hosts, alternate paths, queries and fragments are refused. The proxy streams bounded chunks (100 MiB maximum). Unknown-length overflow/upstream failure omits the HTTP completion marker, causing browser fetch to reject instead of accepting a truncated success. The client checks declared length and the same byte maximum; incomplete media creates no Blob and offers download-only retry. Upstream video HTTP error bodies are closed without reading and replaced by fixed bounded safe diagnostics. No upstream error headers/bodies are reflected.

Cold Email, Model Jury and planning-only Motion Trimmer UI/engines/prompts/request bodies are unchanged. No automatic video fallback, regeneration, image upload, composition, stitching or added music was introduced.
